---
title: Wings TLS and ACME
description: Native TLS on the Wings API listener, Let's Encrypt ACME support over TLS-ALPN, or running Wings behind a reverse proxy.
---


The panel needs to reach Wings over the node's connection URL. If that URL starts with `https://`, the API listener on Wings must present a valid TLS certificate accepted by the panel.

## Option 1 — Automatic ACME certificates (TLS-ALPN)

Wings supports obtaining and renewing certificates automatically via Let's Encrypt using the TLS-ALPN challenge:

```yml
api:
  host: 0.0.0.0
  port: 443
  ssl:
    enabled: true
    acme_domain: node.example.com
    acme_email: admin@example.com
    acme_production: false
```

| Key | Meaning |
|-----|---------|
| `acme_domain` | The public FQDN pointing to this node. |
| `acme_email` | Contact email address registered with Let's Encrypt. |
| `acme_production` | Set to `false` initially to test against Let's Encrypt staging. Set to `true` for valid production certificates. |

<Callout type="warn" title="Port 443 required for TLS-ALPN">
  The Let's Encrypt TLS-ALPN challenge requires inbound traffic on port 443. Set `api.port: 443` and ensure port 443 is accessible in your firewall when using ACME.
</Callout>

## Option 2 — Manual certificates

If you generate certificates using Certbot, Caddy, or a wildcard provider, specify absolute paths to your PEM files:

```yml
api:
  host: 0.0.0.0
  port: 8081
  ssl:
    enabled: true
    cert: /etc/panasaurus/tls/fullchain.pem
    key: /etc/panasaurus/tls/privkey.pem
```

Ensure the certificate and private key files are readable by the process running Wings.

## Option 3 — Reverse proxy (Nginx or Caddy)

You can terminate TLS behind a reverse proxy such as Nginx or Caddy while Wings listens on `127.0.0.1:8081` with `ssl.enabled: false`.

Example Nginx configuration:

```nginx
server {
    listen 443 ssl;
    server_name node.example.com;

    ssl_certificate     /etc/letsencrypt/live/node.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/node.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

<Callout type="info" title="Websocket Headers">
  WebSocket upgrade headers (`Upgrade` and `Connection`) must be forwarded by your proxy for web console and file streaming to work properly.
</Callout>
