---
title: Wings SFTP
description: How SFTP works on Panasaurus Wings — authentication, file operations, and concurrency limits.
---


Panasaurus Wings runs a built-in SFTP server implemented in Rust using `russh`. This allows users to access and manage server files over SFTP using standard SSH/SFTP clients without granting shell access on the host node.

By default, SFTP listens on port **2022** (`system.sftp.bind_address` and `system.sftp.bind_port` in `config.yml`).

```bash
sftp -P 2022 username.serveridentifier@node.example.com
```

## Authentication

SFTP users authenticate with their panel credentials. The username format is `username.serveridentifier` (e.g., `john.a1b2c3d4`), where `serveridentifier` is the short ID of the server.

When a client attempts to log in:
1. Wings verifies the username and password against the panel's authentication API in real time.
2. File permissions (read, write, delete, create) are validated against the user's panel permissions and server egg denylists before modifications touch disk.

## Security & Sandboxing

SFTP sessions in Wings are strictly sandboxed:
- Users cannot navigate outside their server's volume directory (`/var/lib/panasaurus/volumes/<server_uuid>`).
- Symlinks pointing outside the server directory are rejected.
- Direct system shell execution over SSH is disabled; SFTP channel requests are strictly constrained to file transfer operations.

## Limits & Concurrency

SFTP concurrency and handle limits are configured in `config.yml`:

| Configuration Key | Description |
|-------------------|-------------|
| `system.sftp.max_handles` | Maximum open file handles allowed per session (default `64`). |
| `limits.sftp_connections` | Maximum concurrent SFTP connections allowed across the node (default `64`). |
